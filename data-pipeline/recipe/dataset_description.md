## 데이터 생성 파이프라인

```
crop_data.json (182개 작물)
        │
        ▼
[1단계] crawl_10000recipe_final.py
        ├─ 작물명으로 관련 태그 검색
        ├─ 태그별 추천순 1위 레시피 수집
        └─ 품질 필터 (재료 ≥2, 조리단계 ≥2)
        │
        ▼  raw_10000recipe.backup964.json (964건)
        │
[2단계] recover_dropped.py
        └─ 이전 필터에서 누락된 105건 재수집
        │
        ▼  recovered_dropped.json
        │
[3단계] filter_mismatch_v2.py
        ├─ 작물명-재료 매칭 검증
        └─ 미매칭 레시피 제거
        │
        ▼  raw_10000recipe.json (1,025건, 최종)
```

## 1단계: 작물 등급 분류 및 크롤링

### 등급 분류 기준

작물 182개를 활용 빈도에 따라 A/B/C 3단계로 분류하고, 등급별로 수집 태그 수 상한을 설정했습니다.

| 등급 | 해당 작물 예시 | 태그 상한 | 이유 |
|------|--------------|-----------|------|
| **A급** (20종) | 배추, 무, 양파, 마늘, 고추, 감자, 고구마, 대파, 당근, 시금치, 깻잎, 상추, 오이, 호박, 토마토, 가지, 부추 등 | 20개 | 일상에서 자주 쓰이는 주재료성 채소 |
| **B급** (~33종) | 딸기, 사과, 브로콜리, 파프리카, 연근, 우엉, 도라지, 감귤, 레몬, 생강, 인삼 등 | 10개 | 요리 활용도가 중간인 식재료 |
| **C급** (나머지 ~129종) | 두릅, 울외, 삼채, 가지버섯, 방풍나물, 얼갈이배추 등 희귀·특수 작물 | 5개 | 검색 결과가 적거나 활용 빈도가 낮은 작물 |

### 수집 방식

1. 작물명으로 만개의레시피 검색 → 관련 태그 목록 추출
2. 각 태그에 대해 **추천순 1위** 레시피의 상세 페이지 파싱
3. 재료 목록(`ingre_list_name`) + 조리 단계(`view_step_cont .media-body`) 추출
4. 10건마다 중간 저장하여 중단 후 재시작 지원
5. 요청 간 1~1.5초 딜레이로 서버 부하 방지

## 2단계: 누락 레시피 복구

1단계 필터(품질 기준)에서 제외된 105건을 개별 (작물, 태그) 쌍으로 재수집했습니다.
이 과정에서 품질 필터를 적용하지 않고 원본 데이터를 그대로 복원했으며, 미매칭 검증(3단계)에서 최종 판별합니다.

---

## 3단계: 재료-작물 미매칭 필터

수집된 레시피가 해당 작물과 실제로 관련이 있는지 검증합니다.

### 매칭 기준

**(1) 작물명 직접 포함** — 재료 전체를 이어붙인 문자열에 작물명이 포함 (띄어쓰기 무시)
```
예) crop_name="상황버섯", 재료에 "상황버섯" 포함 → 유지
```

**(2) 별칭/허용 변형 매핑** — 작물명과 동일 재료의 다른 표기를 허용
```
예) 감귤 → "귤" 포함 시 유지
    서리태 → "검은콩", "검정콩", "흑태" 포함 시 유지
    고추냉이 → "와사비" 포함 시 유지
    포도 → "청포도", "거봉", "샤인머스캣" 포함 시 유지
```

**(3) 수동 예외 허용(KEEP_OVERRIDE)** — 재료 문자열에 포함되지 않아도 레시피명이 해당 작물 요리임이 명백한 경우
```
예) (미나리, 미나리김밥), (상추, 상추튀김), (인삼, 인삼차)
```

### 제거 사례

| 작물 | 태그(검색어) | 실제 레시피 | 제거 이유 |
|------|------------|-----------|----------|
| 기장 | 기장 | 소고기장조림 | "기장"이 아닌 "소고기장(醬)" |
| 살구 | 살구 | 삼겹살구이 | "살구이(살구+구이)" 오매칭 |
| 무 | 무 | 콩나물무침 | "무침(무치다)"에 매칭된 오류 |
| 치커리 | 치커리 | 시금치커리볶음 | "시금치커리"에 포함된 오매칭 |

## 데이터 스키마

| 필드 | 타입 | 설명 |
|------|------|------|
| `recipe_id` | string | 만개의레시피 고유 ID |
| `recipe_name` | string | 레시피 전체 이름 |
| `tag` | string | 검색에 사용된 태그 (작물 관련 검색어) |
| `crop_name` | string | 대응 작물명 (crop_data 기준) |
| `servings` | string | 인분 정보 (예: "2인분", "4인분") |
| `cook_time` | string | 조리시간 (예: "30분 이내", "1시간 이내") |
| `ingredients` | array[string] | 재료 목록 (이름 + 용량) |
| `instructions` | array[string] | 조리 단계별 설명 |
| `source` | string | 고정값 `"10000recipe"` |
| `source_url` | string | 원본 레시피 URL |
| `crawled_at` | string | 수집 시각 (ISO 8601, UTC) |
| `content` | string | RAG용 통합 텍스트 (아래 참고) |

### `content` 필드 구성

벡터 임베딩 및 RAG 검색을 위해 주요 정보를 하나의 문자열로 결합합니다.

```
레시피명: {recipe_name}
작물: {crop_name}
재료: {ingredients 콤마 연결}
조리법: {instructions 공백 연결}
인분: {servings}
```
