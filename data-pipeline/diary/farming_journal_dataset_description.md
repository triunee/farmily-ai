## 2. 전처리 과정 요약

### 2-1. 품종명 정규화

자유 입력된 품종명을 `crop_data.json`의 표준 작물명으로 통일했다.

- **1단계 — 완전 일치**: `"방울토마토"` → `"방울토마토"` (그대로)
- **2단계 — 포함 관계**: `"설향딸기"`, `"죠향딸기"` → `"딸기"`
- **3단계 — 별칭 사전**: `"천혜향"`, `"한라봉"` → `"감귤"`

### 2-2. 작업유형 정규화

`농작업명` 자유 텍스트를 Farmily 앱의 6종 고정값으로 매핑했다.  
`"기타작업|"` 접두어가 붙은 원본값은 접두어를 제거한 뒤 `detail`에 보존한다.

| 매핑 키워드 (일부) | 매핑값 |
|---|---|
| 수확작업, 딸기따기, 방울토마토따기, 수확, 따기, 채취, 출하 | `수확` |
| 가지치기, 적엽, 순따기, 순지르기, 적아, 정지, 전지, 전정, 도장지 | `기타 농업활동` |
| 파종, 모내기, 정식, 이식, 육묘 | `파종·모내기` |
| 관수, 물주기, 물관리, 급수 | `관수` |
| 제초, 김매기, 풀베기, 잡초 | `제초` |
| 경운, 로터리, 쟁기 | `경운` |
| (키워드 미매칭 전체) | `기타 농업활동` |

### 2-3. 지역-작물 교차 검증

농가 주소의 시/도·시군 정보를 `crop_data.json`의 `origin_region`과 비교하여 산지 일치 여부를 판별했다.

- 지역-작물 매칭 성공: **99,005건 (57.4%)**
- 매칭 실패(타 지역 재배 등): 73,431건 (42.6%)

### 2-4. 날짜 보정

원본 `작성일시`가 `YYYY-MM` 형태인 경우 일(day)을 `01`로 보정하여 `DATE` 타입으로 변환했다.  
형식 불명 또는 파싱 불가 시 `2024-01-01`로 대체한다.

## 4. 최종 선별 데이터셋 — 5개 농가

### 선별 방식

1·2위는 알고리즘 점수 상위 농가를 그대로 유지하고, 3·4·5위는 Farmily의 지역 특산물 스토리텔링 전략에 맞춰 **산지 대표성**을 기준으로 수동 교체했다 (`make_custom_selection.py`).

| 구분 | 순위 | 선별 방식 |
|---|---|---|
| 알고리즘 선별 유지 | 1·2위 | 필수 4개 조건 + 가점 점수 상위 |
| 수동 교체 | 3·4·5위 | 지역 특산 농가 직접 지정 (산지 대표성 우선) |

```
data/farming_journal/
├── raw/

├── ref/
│   └── crop_data.json                       ← 농식품우리누리 작물 지식 (전처리 참조)
└── output/
```

### selected_farmers_custom.json 구조

```json
[
  {
    "farmer_id": 농가일련번호 (int),
    "rank": 선별 순위 (1~5),
    "address": 전체 주소,
    "region": "시도 시군" (2단계),
    "crop_name": 정규화된 작물명,
    "crop_origin_raw": 원본 품종명,
    "origin_region": 산지 문자열,
    "selection_score": 알고리즘 점수 또는 null (수동 지정 시),
    "diary_count": 일지 건수,
    "work_types": [포함된 작업유형 목록],
    "crop_knowledge": {
      "crop_name": 작물명,
      "origin_region": 산지,
      "season_month": 제철 월 (int),
      "harvest_months": [수확 가능 월 목록]
    },
    "farm_diaries": [
      {
        "diary_date": "YYYY-MM-DD",
        "memo": "생육상황: ..." 또는 null,
        "diary_work_blocks": [
          { "sort_order": 0, "work_type": "...", "detail": "..." }

      }
    ]
  }

```

`selection_score`는 알고리즘 선별(1·2위)만 값이 있고, 수동 지정(3·4·5위)은 `null`이다.

## 7. Farmily DB 적재 대상 테이블

선별된 5개 농가 데이터는 아래 테이블에 INSERT된다.  
적재 대상 SQL 파일은 `seed_farming_journals_v2.sql` (`selected_farmers_custom.json` 기반)이다.

```
users (5건) → subscriptions (5건) → farm_profiles (5건)
→ farm_locations (5건) → crops (5건) → farm_diaries (60건)
→ diary_work_blocks (1,411건) → crop_knowledge (5건)
```

| 테이블 | 건수 | 비고 |
|---|---|---|
| `users` | 5건 | kakao_id = `seed_farmer_{farmer_id}` |
| `subscriptions` | 5건 | FREE 플랜 자동 적용 |
| `farm_profiles` | 5건 | |
| `farm_locations` | 5건 | label = `본농장` |
| `crops` | 5건 | 작물별 color_hex 고정 |
| `farm_diaries` | 60건 | 농가당 12건, weather_source = MANUAL |
| `diary_work_blocks` | 1,411건 | sort_order 0부터 순번 |
| `crop_knowledge` | 5건 | crop_data.json 대응 레코드 |

모든 INSERT는 `ON CONFLICT DO NOTHING` 또는 `DO UPDATE`로 멱등성을 보장하여 재실행 시 중복 삽입이 발생하지 않는다.
